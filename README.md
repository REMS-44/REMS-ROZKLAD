# РЕМС-РОЗКЛАД v1.6.1 — виправлення синхронізації v1.6.0

### Що виправлено

v1.6.0 могла сприймати старі записи розкладу як змінені тільки тому,
що міграція дописувала їм порожні поля потоків.

Тепер:
- старі записи не отримують audienceGroups / disciplineIds / source... без потреби;
- нові потокові записи ці поля зберігають;
- порівняння Firestore не залежить від порядку полів документа;
- звичайне збереження не повинно намагатися масово переписати старий розклад.

### Головна зміна безпеки

Якщо Firebase не прийняв зміну через мережу, правила або технічну помилку:
- зміна лишається у цьому браузері;
- система НЕ підвантажує поверх неї стару серверну копію;
- повідомлення показує точний код і місце помилки.

Наприклад:
`permission-denied · teachers · 1 змін`
або
`aborted · розклад · запис 123 · 03.09.2026 · Політологія`

Лише справжній логічний REMS_CONFLICT повертає серверний стан.
