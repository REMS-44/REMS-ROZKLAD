# РЕМС-РОЗКЛАД v1.7.0 — економний realtime Firebase

## Чому було 87 Snapshot listeners

Для адміністратора стара схема тримала:
- settings;
- groups;
- students;
- rooms;
- teachers;
- curricula;
- disciplines;
- lessonTypes;
- schedule;
- roomBookings;
- плюс окремо profile користувача.

Тобто приблизно 11 слухачів на одну відкриту сесію.

## Тепер

Для адміністратора / диспетчера:
- profile користувача;
- settings;
- один catalog signal;
- schedule;
- roomBookings.

Тобто приблизно **5 слухачів замість 11**.

Сім довідників:
groups / students / rooms / teachers / curricula / disciplines / lessonTypes
більше НЕ мають постійних onSnapshot.

Вони:
1. читаються один раз при вході;
2. коли адміністратор реально змінює довідник, у Firebase пишеться один маленький catalog signal;
3. інші відкриті клієнти дочитують тільки ті довідники, які змінилися.

## Прибрано подвійне читання schedule при вході

Раніше:
1. getDocs(schedule);
2. одразу після цього onSnapshot(schedule) знову читав усю колекцію.

Тепер:
- статичні дані читаються один раз;
- schedule і roomBookings беруться одразу з першого realtime snapshot.

Тобто одна й та сама динамічна колекція більше не читається двічі при кожному підключенні.

## Виправлено повернення старого довідника

Раніше realtime listener мав власну стару копію state.
Після локального збереження remoteState оновлювався,
але listener міг пізніше застосувати старі teachers / disciplines / groups.

Тепер є один shared liveState.
Після успішного save саме новий стан стає baseline для:
- записів;
- realtime;
- наступних snapshot.

Це важливо для проблеми «додав викладача / дисципліну, а вона потім зникла».

## Фонові вкладки

Якщо вкладка прихована більше 10 хвилин:
- data listeners відключаються;
- вкладка не продовжує споживати realtime reads у фоні;
- після повернення з'єднання відновлюється автоматично.

## У Налаштуваннях

У блоці Firebase тепер видно:
**Економний realtime**
і фактичну кількість активних слухачів у цій вкладці.

Для адміністратора очікуємо приблизно 5 разом із profile.

## Що тестувати після скидання квоти

1. Відкрити ОДНУ вкладку РЕМС-Розкладу.
2. Перевірити в Налаштуваннях кількість listeners.
3. Змінити одну маленьку річ.
4. Переконатися, що статус повернувся в «Онлайн».
5. Через деякий час порівняти Firebase Usage:
   - Snapshot listeners;
   - Reads;
   - Writes.
